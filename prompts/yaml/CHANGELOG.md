## v2.0.0 — 2026-07-29（V4.5 报告质量重构）

> 提交 91c7c2bb。结构性变更：report/reflection 方法论重写，finance 口径修正，supervisor 路由优化。

### report.yaml（内部 version 1.0.0 → 2.0.0）

#### 新增：核心方法论「数据 → 洞察 → 根因 → 建议」

- 位置：`system_prompt` 开头新增
- 原因：报告"有数据无洞察"，不符合 B 端决策场景
- 影响：分析流程强制四步：先呈现数据 → 提炼模式 → 推断根因 → 给出行动

#### 重写：查询型报告输出结构

- 移除：只输出表格 + 1-2 句总结
- 新增：标题 + 数据表格 + 关键洞察（2-4 个要点：Top 3 及合计占比 / 头部与尾部差距倍数、是否二八分布 / 显著偏离均值的异常标记）+ 可选行动建议
- 原因：纯表格缺乏解读价值，完整报告又过度
- 影响：查询型从"数字罗列"升级为"表格 + 洞察"

#### 重写：分析型报告结构

- 移除：核心结论/数据分析/问题与风险/优化建议
- 新增：执行摘要（含关键数字）/ 核心发现（每项必须"具体数据 → 业务含义"）/ 异常与风险 / 行动建议（每条标优先级，格式"针对[对象]→[动作]→[预期效果]"）
- 原因：与四维质检标准对齐，降低重试率

#### 新增：质量要求段 + 格式规则

- 数据一致性 / 逻辑严谨性 / 可操作性 / 完整性四项，与 reflection 四维质检一一对应
- 表格必须 Markdown 管道符语法；禁止手动加总精确值；禁止声明表格行数或门店总数；汇总用近似值（如"约4.8万元"）
- 原因：LLM 手算求和常出错、"共100家门店"与表格实际行数冲突，导致质检反复不过

#### 精简：输出量控制

- 保留 07-07 的分类逻辑（迭代 9），措辞精简

### reflection.yaml（内部 version 1.0.0 → 2.0.0）

#### 新增：报告类型分诊

- 先判断报告类型：A 数据查询型 / B 综合分析型，再用对应标准检查
- A 型不要求"责任部门""预期执行时间"等管理要素
- 原因：一套标准查两类报告，把查询型报告的简洁误判为"不完整/不可执行"

#### 修改：数据一致性检查口径

- 从"各 Agent 结论是否矛盾"改为"报告数据与原始查询结果是否一致"
- 新增：接受 ±5% 舍入误差，不因微小四舍五入判不通过
- 原因：舍入误差导致的误杀让 LLM 做无意义重试，浪费 3000-5000 token/次

### finance.yaml

#### 修正：退款率口径

- 从"退款订单数/总订单数"改为"退款总金额/销售总金额"
- 原因：与经营看板口径统一，两个页面数字矛盾让用户失去信任
- 影响：模板 1/2/4 全部加 COALESCE/NULLIF 防除零

#### 修复：AVG + ROUND 类型错误

- `ROUND(AVG(...),2)` → `ROUND(CAST(AVG(...) AS numeric),2)`
- 原因：PostgreSQL 中 AVG 返回 numeric，直接 ROUND 在部分环境报类型错误

### supply_chain.yaml

**修复：AVG + ROUND 类型错误**（物流时效、品类采购结构两处模板，同上）

### supervisor.yaml

#### 修改：模糊问题路由策略

- 从"调用全部 Agent（宁可多分析）"改为"按业务关键词选 1-2 个最相关 Agent，完全无法判断才调用全部"
- 原因：模糊问题全量调用浪费 token 且报告发散
- 附带：Inventory Agent 关键词扩充（商品/产品/状态/批次/保质期/品类），提升路由命中率

## v1.2.0 — 2026-07-07

### report.yaml + report_prompt.py（Python 兜底同步）

#### 修改：输出量控制指令拆分

- 移除："最高/最多/最大/第一"等最高级问题 → 只输出一句话结论
- 新增：唯一答案类（"哪家/哪个/谁"）→ 一句话结论；排序类（"Top N""最高/最低的N家""排名前N"）→ 必须 Markdown 表格列出全部 N 条
- 原因：字面关键词无法区分"哪家最高"（一句话）与"最高10家"（表格）两种意图
- 影响：Top N 查询不再被误压成一句话，唯一答案查询不再输出冗长表格
- 验证：无独立验证记录（提交 d393e19d，与 Redis 降级修复同批）；规则在 v2.0.0 重构中保留

## v1.1.0 — 2026-06-12

### report.yaml

#### 移除：报告末尾信任分级指令

- 删除位置：`system_prompt` 末尾合规要求段 + `human_template` 强制要求段
- 原因：前端 `appendReportBubble()` 已硬编码信任分级 HTML（带样式和图标），LLM 同时输出导致重复显示
- 影响：报告末尾不再出现 LLM 生成的信任分级文字，由前端统一渲染
- 验证：admin 和 zhangsan 账号测试，信任分级只出现一次

### report_agent.py（Python 代码层）

#### 修复：FOLLOWUP 提取使用字符串感知括号计数

- 问题：正则 `\[FOLLOWUP:(\[.*?\])\]` 的非贪婪匹配在 JSON 字符串内遇到 `]` 时提前截断
- 方案：改为括号计数法 + `in_string` 状态追踪，跳过字符串内的 `]`
- 影响：追问问题包含 `]` 字符时不再丢失

#### 修复：`encode_chart_markers` 兜底逻辑

- 问题：`|height=` 锚点缺失时整个编码器崩溃
- 方案：未找到 `|height=` 时直接用 `]` 定位标记末尾
- 影响：LLM 截断或畸形输出不再导致报告内容丢失

| reflection | `reflection.yaml` | 1.0.0 | 质量审核：4 维度（一致性/逻辑/可操作/完整） |

### 设计原则

1. **查询型 vs 分析型分离**：用户问具体数据（如"Top 3"）只输出表格，不生成完整报告
2. **输出量控制**：最高级问题只输出一句话，排名问题按 Agent 返回内容输出
3. **数据诚实**：Agent 必须通过 `run_sql` 查真实数据，Prompt 禁止编造
4. **图表嵌入**：`[CHART:type|params]` 标记放在报告对应段落之后
5. **追问建议**：`[FOLLOWUP:["q1","q2","q3"]]` 放在报告末尾

## Prompt 管理机制

### 三级优先级

```text
1. customer_schema.yaml → PromptBuilder 动态生成（客户定制）
2. prompts/yaml/*.yaml → YAML 外部化（热重载）
3. prompts/*.py → Python 硬编码（兜底）
```

### 热重载

```bash
# 无需重启服务
curl -X POST http://localhost:8002/api/v1/prompts/reload \
  -H "Authorization: Bearer $TOKEN"
```

### 版本规范

- 主版本号：Prompt 结构性变更（如新增/删除段落）
- 次版本号：措辞优化、输出格式调整
- 修订号：错别字修复、标点修正
