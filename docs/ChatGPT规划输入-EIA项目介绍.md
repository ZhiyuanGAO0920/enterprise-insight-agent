## 0. 一句话说明

**Enterprise Insight Agent（EIA）V4** 是一个面向连锁零售的 Multi-Agent AI 经营分析平台：用户用自然语言提问，系统在 60 秒内返回一份诊断报告（数据概览 + 根因诊断 + 可执行建议）。我（高志远）以**独立产品负责人**身份完成全部产品设计、架构决策与评估体系建设，代码全部自己写（借助 Claude Code 辅助）。

**项目核心用途**：求职作品集（AI 产品经理岗位）+ 面试实战素材 + 技术能力证明。这是"带真实数据、可演示、有测试和评估体系"的完整项目，不是 demo 玩具。

## 2. 系统架构

```
Supervisor（规划路由，temperature=0）
    ↓ LangGraph Send 并行扇出
[sales] [crm] [finance] [inventory] [supply_chain]  ← 5 领域 Agent
    ↓ 扇入
Aggregator（纯 Python 聚合，不耗 Token）
    ↓
Chart Advisor → Report Agent（SSE 流式输出）→ Reflection Agent（4 维质检，最多重试 1 次）
    ↓
Save Memory（pgvector 1024 维，BGE-M3 本地 Embedding）
```

- **11 个 Agent 节点**：supervisor（路由）、5 领域 Agent（sales/crm/finance/inventory/supply_chain）、aggregator、chart advisor、report agent、reflection agent、memory
- 编排：LangGraph StateGraph + Send 并行扇出/扇入
- 报告输出：SSE 流式（"打字机"效果），查询型→表格+关键洞察，分析型→完整报告（双模式输出）
- 质检：Reflection 4 维（一致性/逻辑/可操作/完整），重试 1 次（实测：0 次→25% 报告有问题；1 次→修复率 60%；2 次边际递减）

| 层 | 技术 |

## 4. 核心产品决策（决策记录，面试可讲）

| # | 决策 | 一句话理由 |
|---|------|-----------|
| 1 | Multi-Agent 而非单 Agent | 上下文竞争（3000 token 数据库结构）+ 注意力衰减 + 故障隔离 + 迭代效率 |
| 2 | Reflection 重试 1 次 | 0 次→25% 报告有问题；1 次→修复率 60%；2 次边际递减（成本 3000-5000 token） |
| 3 | 流式优先 | 95%+ 查询是新问题，缓存命中率极低 |
| 4 | 数据库结构三层适配器 | 自动发现→YAML 映射→Prompt 生成，零驻场部署 |
| 5 | 双模式输出 | 查询型→表格+关键洞察；分析型→完整报告 |
| 6 | 经营看板作为首页 | 解决用户"冷启动焦虑" |
| 7 | 金丝雀评估闭环 | eval 结果落库（eval_runs 带 model_version），16 条固定子集每周跑分，与基线对比超阈值自动告警（模型漂移检测） |
| 8 | 应用内 asyncio 定时兜底 | n8n CLI 导入工作流 cron 注册异常，改为应用内定时（每日 13:05 空闲时段，省 50% 成本），n8n 保留双保险 |
| 9 | PII 集中脱敏 2 拦截点 | sql_runner 结果出口 + 审计日志 query_params，报告/图表下游天然安全，无需逐点处理 |
| 10 | 成本治理 | 2026-08 DeepSeek 分时定价 + 金丝雀错峰调度 + 待办成本硬限额（T-04） |

## 8. 已知痛点 / 风险（供计划参考）

1. **2 条测试环境失败**：LLM API 连接问题（网络/配额），重跑可恢复，非代码问题
2. **n8n CLI 导入工作流 cron 注册异常**：已用应用内定时兜底，n8n 侧工作流模板 connections 是坏的（手工建的无碍）
3. **eval_runs 真实记录少**：金丝雀趋势图需 ≥2 条记录才有意义，数据积累中
4. **RAG SQL 检索命中率 0%**（T-10）：相似 SQL 复用链路实际不可用
5. **Reflection "可操作性"维度占比仅 4%**（T-09）：质检维度与用户满意度关联弱，"passed 28% vs failed 25%" 不准确率问题
6. **前端静态文件缓存坑**：改 static 必须 bump `?v=` 版本号，否则浏览器命中旧缓存
7. **DeepSeek 配额成本敏感**：金丝雀跑分每次消耗配额，需控制频率（当前每周一次）
8. **多租户安全是最大短板**：T-01/T-02 两项高危未修，接入真实客户前必须解决
