# 监控页指标设计原则 —— 决策台而非数据仓库

> 沉淀于 V4.6.6（2026-08-06）：四维度评测（任务结果/执行过程/成本效率/安全体验）的产物。
> 本文回答一个产品问题：**AI Agent 的质量监控界面，13 项候选指标里哪些该展示、哪些该排除、为什么。**

---

## 一、核心原则：一个指标常驻屏幕，必须同时满足三个条件

监控界面的本质是**「决策台」而非「数据仓库」**。缺一不可：

1. **有阈值能判好坏** —— 看到数字就知道健不健康，而不是"哦，知道了"
2. **变化可行动** —— 异常出现后，你知道下一步干什么（能定位、能下钻）
3. **变化频率配得上刷新频率** —— 一年变一次的数据放实时界面是噪音

> 面试话术："产品经理做监控的第一件事不是加指标，而是砍指标。每个常驻指标都应该能回答'现在健康吗、比上周好吗、坏了我去哪查'，满足不了的就下钻，下钻不了的进离线报告。"

---

## 二、13 项候选指标的裁决表

| 维度 | 指标 | 裁决 | 理由 |
|------|------|:---:|------|
| 任务结果 | 任务成功率 | ⚠️ 半上 | 用「分析总量 + 质检未过 + 异常会话」组合表达；单看"成功率"反而说不清失败在哪 |
| | 一次性完成率 | ✅ 上 | 就是重试率（5.9%）+ 修复率（100%），有阈值、可行动 |
| | 目标达成率 | ❌ 排除 | 太抽象，PM 自己都说不清阈值；拆成具体指标（延迟 P95、超时数）才可行动 |
| | 人工介入率 | ❌ 排除 | 无数据源；兜底下钻明细本质就是人工介入清单 |
| 执行过程 | 平均步骤数 | ❌ 排除 | 架构指标，一年不变，看到了不能干什么 |
| | 工具调用成功率 | ✅ 上 | 就是 Agent 错误率排行（inventory 5.7% 一眼可见）；细到 SQL 级则过度 |
| | 规划合理性 | ❌ 排除 | 无实时定义，只能离线抽检路由正确性 |
| | 死循环/超时率 | ✅ 上 | 错误三桶分类（超时/SQL/其他）+ 异常会话卡 |
| 成本效率 | 单任务平均成本 | ✅ 上 | **¥0.0276/任务是全场最值钱的卖点数据**，必须单独展示 |
| | 任务完成耗时 | ✅ 上 | P50/P95 + 完整分析分位分布 |
| | Token 利用率 | ❌ 排除 | 无业界标准定义，容易做成自我感动 |
| 安全体验 | 高危操作拦截率 | ❌ 排除 | 只读架构下事件低频（近乎 100%/0 事件），**展示永不变化的数字没有信息量**；进审计日志 |
| | 幻觉错误操作率 | ❌ 排除 | 无法实时度量；用「不准确率 + 离线算术审计」两个 proxy 替代 |
| | 用户信任分 | ✅ 上 | 好评率 + 反馈趋势 |

**裁决结果：13 项 → 8 项上界面，4 项主动排除，1 项拆解下沉。**

---

## 三、分层架构：排除不等于丢弃

被排除的指标不是不重要，是**放错了层**：

```
┌─ 实时层（界面常驻）  ：成功率/重试修复率/延迟/成本/好评率/Agent错误率 → 一眼健康
├─ 诊断层（点击下钻）  ：质检四维分布/兜底明细/错误日志 → 异常时定位
└─ 离线层（周报+评估集）：步骤数/规划合理性/安全审计/幻觉审计 → 复盘时看
```

---

## 四、两条隐藏原则

### 4.1 指标要「成对」看，单看会骗人

最有力的实证是 **质检通过率 × 好评率同屏** —— V4.6.3 的"零相关"重磅发现（质检过的报告不准确率 28% vs 未过 25%），**就是这对指标放一起才浮出来的**。单独看任何一个都岁月静好。V4.6.6 据此把 hero 扩为四象限：

```
📊 日均分析量 × ✅ 质检通过率 × ⚡ P50 延迟 × ⚠️ 异常会话
业务量           质量            速度            稳定性
```

量·质·速·稳，四个象限各司其职，交叉检视。

### 4.2 诚实标注口径，用透明换信任

- 异常会话 = 至少一次技术异常事件（实测全为超时）的会话，**多数经重试自愈仍产出报告** —— 不夸大
- DB 无法区分「质检跳过」与「真过」——就如实标注"可查的最大细分是三态"
- 兜底报告可下钻，并明确警示「兜底 ≠ 质检通过」

> 面试话术："AI 产品的信任不是靠展示漂亮数字，是靠把指标的盲区也告诉用户。我宁可让监控页看起来'没那么好'，也不让它骗人。"

## 五、V4.6.6 落地（真实数据）

| 新指标 | 口径 | 近 30 天实测 |
|--------|------|------|
| 异常会话 | 受影响会话数（DISTINCT session_id + error 非空） | **26 会话** |
| 异常事件 | 技术异常事件数 | **29 条**（全为超时） |
| 异常率 | 占 trace 会话 %（与重试率同源同窗） | **19.7%**（徽标档「良好」） |
| 单任务成本 | SUM(llm_cost)/COUNT(*) | **¥0.0276** |

**克制清单（本轮主动没做的）**：
- 平均步骤数 / 规划合理性 / 高危拦截率 / 幻觉错误操作率 —— 不上界面
- Token 趋势图 `x¥1e4` 与 React 真实元值的量纲偏差 —— 不动（非本次范围）
- 8 个后端已算但未渲染的字段（followup_rate/daily_trend/health 等）—— 不新增展示
