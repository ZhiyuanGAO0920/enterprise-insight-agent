innerHTML 大量拼接用户/LLM 生成内容（XSS）
app.js:285,490,599,731,751 + views.js 全文
报告内容由 LLM 生成后通过 marked.parse() 转为 HTML 再 innerHTML 注入。虽然 marked 默认不做 XSS 过滤，攻击者若通过 prompt 注入让 LLM 输出 <img onerror=...> 标签，将直接在用户浏览器执行。esc() 仅用于纯文本字段，Markdown 渲染路径完全绕过了转义。
// app.js:731 — LLM 输出直接 marked.parse + innerHTML，无 sanitize var fh; try{ fh=marked.parse(convertTextTables(expandChartTags(ctr))); }catch(e){fh=esc(ctr);} sd2.innerHTML=fh.replace(/\[FOLLOWUP[^\]]*\]\]/g,''); // app.js:285 — 用户名直接拼入 innerHTML（虽有 esc 但路径复杂） var html=f.map(function(u){ return '<tr>...<td>'+esc(u.username)+'</td>...' }).join(''); document.getElementById('apUserList').innerHTML=html;
✅ 修复建议
1. 引入 DOMPurify（~7KB gzip），在 marked.parse() 后统一 DOMPurify.sanitize(html)
2. 配置 marked 的 sanitizer 选项，或升级 marked v5+ 启用内置 sanitize
3. 对 expandChartTags 生成的 data-chart 属性做白名单校验（当前只 try-catch JSON.parse）

P0
onclick 内联事件 + jsEscape 字符串注入
app.js:285,306,619 + index.html:52-154
所有动态生成的 HTML 都通过 onclick="fn('...')" 内联事件绑定，参数由 jsEscape() 转义后拼入字符串。jsEscape 虽然处理了引号和换行，但如果 jsEscape 有遗漏（如反引号、unicode 转义），就会产生 XSS。此外，index.html 中有 20+ 个内联 onclick，违反 CSP 策略。
// app.js:285 — onclick 内联 + jsEscape 拼接 '<a class="action-link danger" onclick="deleteUser('+u.id+',\''+jsEscape(u.username)+'\')">删除</a>' // utils.js:306 — 追问按钮同样内联 return '<button class="followup-btn" onclick="askFollowup(\''+jsEscape(q)+'\')">'+esc(q)+'</button>'
✅ 修复建议
1. 改用 事件委托：在父容器上 addEventListener('click', handler)，通过 data-* 属性传参
2. 示例：<button data-action="delete" data-uid="5" data-uname="admin"> + e.target.dataset 读取
3. 这样可以启用 CSP script-src 'self'，彻底杜绝内联脚本

可访问性：无 ARIA 标签、无键盘导航、无焦点管理
index.html 全文 / app.js — 所有自定义组件
当前界面完全无法用键盘操作。自定义下拉菜单（用户菜单、管理面板筛选器）、模态框（反馈、用户编辑）、Tab 导航、历史记录列表等全部依赖鼠标点击，没有 tabindex、role、aria-label、aria-expanded 等任何 ARIA 属性。模态框打开后焦点不会陷阱在框内，Escape 键无法关闭。
<!-- index.html:91 — 用户菜单按钮无 aria-expanded --> <button class="user-menu-btn" onclick="toggleUserMenu()" aria-expanded="false" aria-haspopup="true" aria-label="用户菜单"> <!-- index.html:194 — 模态框无 role="dialog" / aria-modal --> <div id="feedbackModal" class="modal-overlay" role="dialog" aria-modal="true" aria-labelledby="feedbackTitle">

1. 模态框：添加 role="dialog" aria-modal="true"，打开时焦点移入、关闭时焦点返回触发元素，Escape 键关闭
2. 下拉菜单：添加 aria-expanded / aria-haspopup，支持 Enter/Space 打开、Escape 关闭、上下箭头导航

5. 图表：为每个 chart-container 添加 role="img" aria-label="图表标题"
P1
SSE 错误处理过于宽泛，异常被静默吞掉
app.js:710,745 / 全文 try-catch
SSE 事件解析的 catch(e){console.warn('SSE event parse:',e);} 会吞掉所有 JSON 解析错误和运行时错误。如果某个事件格式变化导致 ev.type 分支内代码抛异常，用户只会看到进度条卡住，没有任何错误提示。同样，restoreSession、loadSessionInfo 等函数的 catch(e){console.warn(e);} 也会让网络错误对用户不可见。
✅ 修复建议
1. SSE 解析失败时记录到错误上报系统，而非仅 console.warn
2. 连续 N 次解析失败后向用户展示"连接不稳定"提示
3. restoreSession 失败应 toast('会话恢复失败，请重新登录') 并跳转登录页
4. 考虑引入全局 window.onerror / unhandledrejection 捕获器

P2
innerHTML 大块替换而非局部 DOM 更新
app.js:179 (KPI 渲染) / 490 (监控面板) / 599 (历史详情)

SSE 流式解析中使用了大量单字母/双字母变量：sr2 (stream response), r2 (reader), dec (decoder), buf (buffer), sc (stream content), fr (final report), fid (final id), fds (final data sources), ffqs (final followup questions), fers (final errors), sb (stream bubble), fh (final html), ext (extra html)。这些命名在 70 行函数内可读性极差。

app.js — loadDashboard / loadHistoryView / loadMonitorOverview
所有数据加载只有两种状态：空白等待 + 数据渲染完成。没有骨架屏（Skeleton Screen）给用户"内容正在加载"的视觉反馈。加载失败时只有 toast('看板加载失败') 一行提示，没有重试按钮。监控面板有 loading spinner，但 Dashboard 和 History 没有。

P2
Toast 2.5s 消失过快 + 无操作按钮
utils.js:76
setTimeout(function(){el.remove()},2500) 让 Toast 在 2.5 秒后自动消失。对于"报告已下载"、"复制成功"等确认型 Toast 尚可，但对于"导出失败"等错误型 Toast，用户可能来不及阅读。也没有手动关闭按钮。
✅ 建议
区分 toast.success(msg)（2.5s 自动消失）和 toast.error(msg)（5s + 关闭按钮）。或统一改为 toast(msg, {duration, type, action})。
P2
var 全局使用，未用 const/let
全文 — 所有 JS 文件
所有变量声明都用 var，没有使用 const / let。var 的函数作用域和变量提升行为容易导致闭包陷阱（如 for 循环中的 var）。虽然当前代码没有明显 bug，但在重构时容易引入。
✅ 建议
配合 ESLint 的 no-var 规则逐步迁移。默认用 const，需要重新赋值时用 let。这个改动风险低、收益高。
P2
搜索输入无防抖
app.js:132 (index.html oninput="filterHistory()")
历史记录搜索框 oninput="filterHistory()" 每次按键都触发过滤。虽然当前是前端过滤（数据量小），但如果历史记录增长到数百条，每次按键都遍历 + innerHTML 重建列表会有卡顿。
✅ 建议
添加 200ms 防抖：var _hvTimer; function filterHistory(){clearTimeout(_hvTimer); _hvTimer=setTimeout(_doFilter,200);}

两个第三方库通过本地 /static/ 路径加载，虽然不涉及 CDN 篡改风险，但如果未来迁移到 CDN，缺少 integrity 属性将无法验证文件完整性。同时 echarts.min.js（~1MB）没有 defer 属性，会阻塞后续脚本。

app.js:196
onEChartsReady(function(echarts){...}) 在 loadDashboard() 中被调用，但在三个 JS 文件中均未找到此函数的定义。如果它在某处通过 window.onEChartsReady = ... 动态挂载，这种隐式依赖很容易在重构时断裂。如果确实未定义，则 Dashboard 图表永远不会渲染。

5. 引入 DOMPurify 作为构建依赖
建议

✅ Design Token 体系
CSS 中定义了完整的 Design Token（背景层 / 表面层 / 边框 / 文字 / 强调色 / 语义色 / 阴影），层级清晰、命名规范。这是很多项目缺失的基础设施。
✅ 缓存策略设计合理
_cachedFetch() 实现了内存缓存 + sessionStorage 双层缓存，Dashboard 数据刷新后可秒级恢复。Admin 面板有 5 分钟 TTL 缓存。缓存失效逻辑（_clearCache）在增删改后正确调用。
✅ SSE 流式体验
流式报告生成体验做得不错：进度条步骤动画 + token 逐字渲染 + 完成后图表注入。AbortController 支持用户中途停止分析。
✅ 打印样式优化
@media print 隐藏了侧边栏、输入框、工具栏，调整了表格和代码块颜色。说明考虑了 PDF 导出场景。
✅ prefers-reduced-motion 支持
CSS 末尾添加了 @media (prefers-reduced-motion: reduce)，为前庭功能障碍用户禁用动画。这是很多项目忽略的可访问性细节。
✅ 响应式覆盖完整
从 480px 到 1280px+ 的断点都有覆盖，移动端布局合理（侧边栏变顶部、KPI 网格 6→3→2 列、图表高度缩减）。
