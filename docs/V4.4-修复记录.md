## 一、前端体验优化（views.js / index.html / style.css）

### 1.1 渐进式流式展示
- **问题**：质量审核通过后报告一次性展示，用户反馈"太过突兀"
- **修复**：审核通过后按 40~50 块渐进渲染（每块 40ms，总计约 2 秒），模拟流式效果
- **文件**：`app/api/static/views.js#L1068-L1129`
- **关键代码**：
  ```javascript
  // 预渲染 HTML 后按块渐进展示
  var chunks = Math.min(50, Math.max(8, Math.floor(totalLen / 30)));
  var chunkSize = Math.max(1, Math.ceil(totalLen / chunks));
  // 每块 40ms，避免在 HTML 标签中间截断
  setTimeout(revealNext, 40);
  ```

### 1.2 滚动到顶部修复
- **问题**：报告生成后停留在页面底部，需手动上滑
- **根因**：`scrollIntoView({block:'start'})` 执行后，post-loop 代码又执行了 `el.scrollTop=el.scrollHeight`，覆盖了滚动效果
- **修复**：有渐进展示气泡时跳过底部滚动（`app/api/static/views.js#L1164`）

### 1.3 渐进展示被 _isAnalyzing 中断
- **问题**：渐进展示在第一次回调时直接 return，气泡始终为空
- **根因**：`revealNext` 检查 `if(!_isAnalyzing)return;`，但 `_isAnalyzing` 在 `try/finally` 的 `finally` 块中被设为 `false`，早于第一个 `setTimeout(revealNext, 40)` 触发
- **修复**：移除 `_isAnalyzing` 检查（渐进展示仅做展示，不影响分析流程）

### 1.4 追问按钮兜底
- **问题**：DeepSeek 模型不生成 `[FOLLOWUP:]` 标记，追问按钮一直不展示
- **根因**：LLM 忽略 prompt 末尾的指令
- **修复**：双重保障
  1. 追问指令改为独立 `SystemMessage`（比嵌在 Human prompt 末尾更醒目）
  2. 规则兜底：从报告中检测"门店""区域""趋势"等关键词，自动生成对应的追问问题（零 LLM 成本，100% 可靠）
- **文件**：`app/agents/report_agent.py#L327-L364`

## 二、质量监控修复（monitor.py + 数据库）

### 2.1 缺少数据库列
- **问题**：质量监控页报"数据查询遇到技术问题"
- **根因**：`analysis_history.followup_questions` 列在 ORM 模型有定义，但无 Alembic 迁移，实际数据库不存在。质量监控概览的第 11 个 SQL 查询引用了该列
- **修复**：
  - `ALTER TABLE analysis_history ADD COLUMN IF NOT EXISTS followup_questions TEXT`
  - `ALTER TABLE agent_trace_events ADD COLUMN IF NOT EXISTS trace_id VARCHAR(64)`（APM 追踪器一直因缺列静默失败）

### 2.2 async with 缩进截断（代码审查发现 #1）
- **问题**：`quality_overview()` 中 `async with get_session() as session:` 块缩进失误，后续 ~180 行代码（含 11 个 SQL 查询）在会话关闭后执行
- **实际影响**：SQLAlchemy 2.0 的 `AsyncSession.close()` 后仍可透明复用（不报 `ResourceClosedError`），但每个查询都重新获取连接
- **修复**：全部缩进到 `async with` 块内，复用同一会话连接

## 三、SQL 安全检查修复（sql_runner.py）

### 3.1 CTE/DML 子类型检测死代码（代码审查发现 #2）
- **问题**：`token.ttype in (Keyword,)` 在 `sqlparse 0.5.5` 中不匹配 `Keyword.CTE`/`Keyword.DML` 子类型
- **根因**：`sqlparse` 的 `_TokenType.__eq__` 非对称，`Keyword.CTE == Keyword` 返回 `False`，`in` 检查失效
- **影响**：CTE（`WITH ... AS`）检测全是死代码，含 CTE 的 SQL 的 RLS 过滤可能注入到错误的表
- **修复**：全部改为 `token.ttype in Keyword`（`_TokenType.__contains__` 正确处理子类型层级）
- **涉及位置**：
  - CTE 跳过检测（`token.value.upper() in ('WITH',)`）
  - CTE 结束检测（`token.value.upper() in ('SELECT',)`）
  - 外层 FROM 查找
  - FROM 后的关键字终止检查
  - Name 类型同理：`t.ttype in (Name,)` → `t.ttype in Name`
