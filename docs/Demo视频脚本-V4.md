### 第六段：分析型问题——华东区销售下降根因（2:25-3:45）★ 核心段落

**画面**：输入框，输入更复杂的问题

**操作步骤**：
1. 输入"最近30天华东区销售为什么下降了？分析具体原因并给出改进建议"
2. 点击发送
3. 流式进度展示（镜头拉近，这是全片重点）：

   ```
   🧠 Supervisor Agent 正在规划...
      → 激活 Sales Agent     (查华东区销售趋势 + 品类明细)
      → 激活 CRM Agent       (查华东区会员活跃度 + 流失)
      → 激活 Finance Agent   (查华东区退款率 + 客单价)
   
   🔍 Sales Agent    正在执行 SQL 查询...
   🔍 CRM Agent      正在执行 SQL 查询...
   🔍 Finance Agent  正在执行 SQL 查询...
        ↓ 3 个 Agent 并行执行，互不阻塞 ↓
   
   📊 Aggregator 聚合 3 个 Agent 分析结果...
   📈 Chart Advisor 推荐图表类型...
   📝 Report Agent 流式生成报告...
   ✅ Reflection Agent 4 维质检（一致性/逻辑/可操作/完整）...
   📥 保存至 pgvector 语义记忆...
   ```

**旁白**（跟随进度实时解说）：
> "现在来一个真正有难度的——'华东区销售为什么下降'。
>
> 这个问题需要跨三个维度——销售趋势、会员活跃度、退款率——传统方式需要三个人分别查数据再拼起来。
>
> 注意看，Supervisor 自动规划：激活 Sales、CRM、Finance 三个 Agent。它们**并行**执行——同时查数据库，互不等待。这是 LangGraph Send 实现的并行扇出。
>
> 每个 Agent 有自己的工具——可以获取表结构、生成 SQL、执行查询。注意右侧面板，每一条 SQL、执行耗时、返回行数都记录下来——数据完全可追溯。
>
> 三个 Agent 完成后，Aggregator 聚合结果——纯 Python 代码，不消耗 Token。Chart Advisor 自动判断需要柱状图还是折线图。Report Agent 流式生成报告——你看到的每一个字都是实时推送到前端的。
>
> 最关键的一步——Reflection 质检 Agent。它从四个维度审核报告：数据一致性、逻辑严谨性、建议可操作性、问题覆盖完整性。不合格自动重写，最多一次。"

**画面**：展示最终报告（滚动浏览）

**旁白**：
> "最终输出包含：数据概览、根因诊断、改进建议三个部分。从提问到拿到报告大约 60 到 90 秒。而传统方式，至少半天。"

- [ ] React 前端已构建（`cd web && npm run build`）或 dev 模式（`npm run dev`）
