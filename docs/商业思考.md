# 商业思考

> 面试官视角：如果候选人只能聊功能、不能聊商业，那就是执行层 PM 而不是产品负责人。
> 本文档覆盖目标市场、定价、GTM、竞争壁垒和为什么不现在做 SaaS。

---

## 一、目标市场

### 市场规模估算

| 层级 | 规模 | 说明 |
|------|------|------|
| **TAM（总可寻址市场）** | ~¥500 亿 | 中国泛零售/餐饮连锁企业 IT 支出 |
| **SAM（可服务市场）** | ~¥50 亿 | 零售经营分析 / BI 工具细分市场 |
| **SOM（可获取市场）** | ¥500 万-2000 万（3 年目标） | 100-1000 家门店的中型连锁零售企业 |

### 目标客户画像

| 维度 | 描述 |
|------|------|
| **企业规模** | 100-1000 家门店，年营收 1-50 亿 |
| **业态** | 连锁零售（超市/便利店/药店/餐饮/服饰） |
| **数字化程度** | 已有 ERP/POS 系统，数据在数据库中但不被利用 |
| **核心决策者** | CEO/VP of Operations（不是 CTO 或数据团队负责人） |
| **核心痛点** | ①看数据依赖分析师取数（慢）②BI 工具培训成本高（学不会）③经营决策靠经验（拍脑袋） |
| **预算能力** | 年 IT 预算 50-500 万，经营分析工具预算 5-20 万 |
| **采购决策链** | CEO 发起 → 运营 VP 评估 → IT 部门配合部署（通常 1-3 个月） |

### 为什么先打中型连锁？

- **太大**（1000+ 家门店）：已有自建 BI 团队 + 帆软/观远年度合同，切入难度高
- **太小**（< 50 家门店）：老板自己看 Excel 就够了，付费意愿弱
- **中型**：有数据但缺分析能力，有预算但请不起专职数据团队——**我们的甜蜜点**

## 二、定价策略

### 定价模型：按门店数收费

| 版本 | 门店数 | 月费 | 年费 | 说明 |
|------|--------|:--:|------|------|
| 免费版 | ≤ 5 | ¥0 | ¥0 | 单店/小微商户体验 |
| 标准版 | 6-50 | ¥199/门店/月 | ¥2,388/门店/年 | 核心功能完整 |
| 专业版 | 51-200 | ¥149/门店/月 | ¥1,788/门店/年 | 含专属 Prompt 定制 |
| 企业版 | 200+ | ¥99/门店/月 | ¥1,188/门店/年 | 含私有化部署 + SL A |

**一个 100 家门店的连锁企业：专业版，年费约 ¥18 万。**

### 为什么按门店数而不是按用户数？

1. **价值感知对齐**：客户的经营规模 = 门店数，而非员工数。100 家门店的老板认为"我为 100 家门店付钱"是合理的，但"我只有 5 个店长用你为什么要按人头收费"就不合理。
2. **避免使用阻力**：按用户数收费会抑制推广——区域经理想让更多店长用，但怕增加费用。按门店收费 = 同一门店不限用户数，推广无阻力。
3. **行业惯例**：零售 SaaS（如收银系统、门店管理系统）普遍按门店收费，客户已习惯此模型。

### 为什么比帆软便宜这么多？

帆软 FineBI 年费通常 ¥10-50 万。我们的定价逻辑不是"比帆软便宜"，而是"比雇一个数据分析师便宜"。一个中级数据分析师年薪约 ¥15-25 万，我们的工具相当于把分析师的日常工作自动化了——¥18 万/年 vs ¥20 万/年 + 社保，ROI 是正的。

## 三、市场进入策略（GTM）

### 阶段 1：创始人-led Sales（前 5 个客户）

| 维度 | 策略 |
|------|------|
| **获客方式** | 行业人脉 + 冷启动 outreach（LinkedIn/行业社群） |
| **目标** | 5 个付费客户，年营收 ¥50-100 万 |
| **核心动作** | ① 免费为前 3 个客户部署 + 深度定制 ② 收集产品迭代反馈 ③ 产出 3 个标杆客户案例 |
| **关键指标** | 客户留存率 > 80%、NPS > 40 |
| **为什么不做内容营销/广告？** | 没有标杆案例的情况下，内容营销没有可信度。先做深 5 个客户，再放大声量。 |

### 阶段 2：内容 + 渠道（10-50 个客户）

| 维度 | 策略 |
|------|------|
| **获客方式** | ① 行业内容营销（公众号/知乎/零售行业媒体）② ERP 系统集成合作 |
| **内容方向** | "如何用 AI 让店长自己做数据分析"、"你的 BI 工具用对了吗" |
| **渠道合作** | 与 ERP/收银系统厂商合作——"买了 XX ERP，一键接入 AI 经营分析" |
| **目标** | 50 个客户，年营收 ¥500-1000 万 |
| **为什么选择 ERP 渠道？** | 客户的数据已经在 ERP 里了，我们的价值是"让这些数据开口说话"。ERP 厂商有客户关系但没有 AI 能力——互补关系。 |

### 阶段 3：规模化（50+ 客户）

产品驱动的增长飞轮已启动：更多客户 → 更多数据 → Prompt 更准确 → 更好的产品 → 更多客户。

## 四、为什么不现在做 SaaS 多租户？

技术栈已经支持（RBAC + 行级数据安全 + Docker 部署），但不做是因为：

**1. 数据安全信任问题（最大障碍）**

连锁零售企业的核心经营数据（销售额、会员、库存、采购成本）是商业机密。他们不会把这些数据放在一个初创公司的云端。**私有化部署是建立信任的前提。**

**2. 决策链更短**

私有化部署的客户决策链：CEO 拍板 → IT 部门部署。SaaS 的客户决策链：CEO → 信息安全委员会（数据出境审查）→ 采购 → IT。多两个环节，周期翻倍。

**3. 先做深一个客户的价值 > 做浅 100 个客户**

私有化部署意味着每个客户都是深度定制的机会：定制 Prompt、定制数据接入、定制报告格式。前 5 个客户的深度反馈，价值大于 SaaS 模式下 100 个浅层用户的行为数据。

**什么时机切 SaaS？** 当有 10+ 个付费客户、积累了大量行业 Prompt 模板和数据方案后，推出 SaaS 版本作为"低门槛试用入口"，私有化部署作为"高端升级方案"。

## 六、竞争护城河（长期视角）

| 阶段 | 护城河 | 如何建立 |
|------|--------|----------|
| **0-5 客户** | 行业专长 | 深度服务前 5 个客户，积累垂直行业的 Prompt 模板和 SQL 查询模式 |
| **5-50 客户** | 切换成本 | 客户将周报/预警嵌入日常工作流（如飞书定时推送），迁移成本逐渐上升 |
| **50+ 客户** | 数据网络效应 | 用所有客户的匿名查询模式训练更精准的 Supervisor 路由和 SQL 模板推荐 |

**核心逻辑**：AI 产品没有不可复制的技术壁垒，但有累积的行业专长壁垒——你知道"连锁零售老板最常问的 20 个问题是什么、每个问题应该查哪些表、最好的分析思路是什么"。这些不是在办公室里凭空想出来的，是在服务真实客户中积累的。

## 七、如果我是面试官，我会问的 5 个商业问题

| 问题 | 我的回答要点 |
|------|------------|
| "你为什么觉得有人会为这个付钱？" | 雇一个数据分析师年薪 ¥20 万，我们的工具 ¥18 万/年且 24 小时在线、1 分钟出报告——ROI 是正的 |
| "如果帆软明天免费了怎么办？" | 帆软免费也不会降低使用门槛——老板还是不会拖拽。我们的价值不是便宜，是零门槛 |
| "你怎么从 0 到第一个付费客户？" | 行业人脉 + 免费试用 1 个月 → 证明价值 → 年合同。第一个客户不求赚钱，求案例 |
| "这个市场规模够大吗？" | 只算中国 100-1000 家门店的连锁零售企业约 3000-5000 家，即使只拿 1% = 30-50 家，年营收 ¥540-900 万。对一个小团队来说足够了 |
| "为什么是你来做？" | 我同时理解连锁零售业务（知道该分析什么）和 AI Agent 技术（知道怎么分析），这个交叉领域的人不多 |
