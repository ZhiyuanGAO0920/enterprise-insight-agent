# A/B 测试记录

> 利用 V4 的 Feature Flag（8 个开关）和 Prompt YAML 热重载机制，对关键产品体验决策进行数据化验证。

---

## 测试 1：图表 vs 纯文本报告

### 实验设计

| 维度 | 设置 |
|------|------|
| **实验目的** | 验证 ECharts 图表是否能提升用户对经营数据的理解速度和理解准确率 |
| **A 版本（对照组）** | 纯 Markdown 表格报告（`FEATURE_CHART=false`） |
| **B 版本（实验组）** | 表格 + ECharts 图表报告（`FEATURE_CHART=true`） |
| **测试问题** | "各区域销售额占比" |
| **测试用户** | 2 位非技术背景测试者 |
| **指标** | ①阅读完报告耗时 ②TOP3 区域正确率 ③趋势判断正确率 ④主观满意度（1-5） |

### 测试数据

| 指标 | A 版本（纯文本表格） | B 版本（含饼图） | 提升 |
|------|:--:|:--:|:--:|
| 阅读耗时（秒） | 22s | 8s | **-64%** |
| 能正确说出 TOP3 区域 | ✅ | ✅ | — |
| 能正确说出各区域占比关系 | ❌ 需要自己心算 | ✅ 一眼看出 | 质变 |
| 主观满意度（1-5） | 3 | 5 | **+67%** |
| 用户原话 | "数据是准确的，但自己要看数字" | "饼图一看就懂了" | — |

### 结论

**图表显著提升了"占比类"数据的理解速度和准确率。** 饼图/柱状图对于"一眼看出大小关系"有不可替代的价值。后续优先级：占比类问题优先推荐饼图，排名类优先推荐柱状图，趋势类优先推荐折线图。

## 测试 2：有溯源 vs 无溯源报告

### 实验设计

| 维度 | 设置 |
|------|------|
| **实验目的** | 验证数据溯源标记是否提升用户对 AI 报告的信任度 |
| **A 版本（对照组）** | 无溯源标记的报告（`FEATURE_DATA_TRACE=false`） |
| **B 版本（实验组）** | 含 [📊 查看SQL] 可点击溯源标记的报告（`FEATURE_DATA_TRACE=true`） |
| **测试问题** | "华东区最近一个月销售额是多少" |
| **指标** | ①主观信任度（1-5）②是否会主动点击溯源 ③对数据准确性的疑虑 |

### 测试数据

| 指标 | A 版本（无溯源） | B 版本（含溯源） | 提升 |
|------|:--:|:--:|:--:|
| 主观信任度（1-5） | 2.5 | 4.5 | **+80%** |
| 主动点击溯源 | N/A | ✅ 100% 点击 | — |
| 用户原话 | "数字对吗？怎么算出来的？" | "我可以看到这个数字是从哪来的，放心多了。" | — |

### 结论

**溯源标记是建立 AI 报告信任的关键功能。** 在没有溯源的情况下，用户对 AI 输出有本能的不信任。溯源标记本身未必每次被点击，但它的存在本身就是"你可以验证我"的承诺——这本身就是信任建立。后续优先级：保持默认开启。

## 测试 3：快捷问题 vs 空白输入框（移动端）

### 实验设计

| 维度 | 设置 |
|------|------|
| **实验目的** | 验证移动端快捷问题入口是否降低用户的使用门槛 |
| **A 版本（对照组）** | 仅有空白输入框 |
| **B 版本（实验组）** | 输入框上方有 6 个快捷问题按钮 + Dashboard 快报卡片 |
| **测试用户** | 2 位首次使用的移动端测试者 |
| **指标** | ①首次提问耗时 ②是否使用快捷问题 ③操作流畅度主观评价 |

### 测试数据

| 指标 | A 版本（纯输入框） | B 版本（含快捷入口） | 提升 |
|------|:--:|:--:|:--:|
| 从打开页面到第一次提问 | 35s（在思考问什么） | 5s（直接点快捷问题） | **-86%** |
| 使用快捷问题 | N/A | ✅ 100% 首次使用点击了快捷问题 | — |
| 后续自发提问 | 仅 1 次 | 3 次（受快捷问题启发） | +200% |
| 用户原话 | "不知道能问什么" | "这些按钮让我知道可以问什么" | — |

### 结论

**移动端空白输入框对首次用户是"冷启动障碍"。** 用户不知道系统能力边界，不知道"能问什么"。快捷问题充当了"能力菜单"的角色，显著降低了首次使用门槛。后续优先级：根据使用数据动态调整快捷问题排列。

## 测试 4：追问建议 vs 无追问

### 实验设计

| 维度 | 设置 |
|------|------|
| **实验目的** | 验证报告末尾的追问建议是否能提升对话深度 |
| **A 版本（对照组）** | 无追问建议（`FEATURE_MULTI_TURN=false`） |
| **B 版本（实验组）** | 报告末尾 3 个追问建议按钮（`FEATURE_MULTI_TURN=true`） |
| **测试问题** | "华东区销售为什么下降" |
| **指标** | ①是否会点击追问 ②总对话轮次 ③追问是否在 Agent 覆盖范围内 |

### 测试数据

| 指标 | A 版本（无追问） | B 版本（含追问） | 提升 |
|------|:--:|:--:|:--:|
| 继续追问 | 0%（不知道问什么） | 100%（点击了追问按钮） | 质变 |
| 总对话轮次 | 1 | 3（初始 + 2 次追问） | +200% |
| 追问内容质量 | N/A | "退款率最高的门店是哪个" + "它的会员流失情况呢" | 连贯 |
| 用户原话 | — | "这些按钮让我顺着思路继续深挖" | — |

### 结论

**追问建议将单次分析转变为连续探索。** 用户在看完报告后往往有"还想继续深挖"的冲动，但不知道该问什么。追问建议充当了"导航"角色——不替用户做决策，但告诉他有哪些路可以走。后续优先级：探索根据用户历史行为个性化追问建议。

## 汇总：Feature Flag 优先级建议

基于以上 4 组测试，各功能对用户体验的影响排序：

| 功能 | Feature Flag | 测试影响 | 建议 |
|------|-------------|:--:|------|
| 图表可视化 | `FEATURE_CHART` | 理解速度 +64%，满意度 +67% | **P0 必须开启** |
| 数据溯源 | `FEATURE_DATA_TRACE` | 信任度 +80% | **P0 必须开启** |
| 多轮对话 | `FEATURE_MULTI_TURN` | 对话轮次 +200% | **P0 必须开启** |
| 移动端快捷 | `FEATURE_MOBILE_UI` | 首次提问耗时 -86% | **P0 必须开启** |
| 用户反馈 | `FEATURE_FEEDBACK` | 持续收集数据中 | P1 建议开启 |
| APM 追踪 | `FEATURE_APM` | 后台性能数据 | P1 建议开启 |
| 友好错误 | `FEATURE_FRIENDLY_ERRORS` | 错误场景体验 | P1 建议开启 |
| Prompt YAML | `FEATURE_PROMPT_YAML` | A/B 测试基础设施 | P1 建议开启 |
