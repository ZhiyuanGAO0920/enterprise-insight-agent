# Enterprise Insight Agent V4 — 启动指南

## 硬件要求

| 组件 | 最低配置 | 推荐配置 |
|------|---------|---------|
| CPU | 4 核 | 8 核 |
| 内存 | 8 GB | 16 GB |
| 磁盘 | 30 GB 可用 | 100 GB SSD |
| 操作系统 | Ubuntu 20.04+ / CentOS 7+ / Windows 10+ (Docker Desktop) |
| Docker | Docker 24+ + Compose V2 | Docker 27+ |

> **内存说明**：Ollama + BGE-M3 嵌入模型需要 2-4 GB 内存。如果不需要语义搜索功能，可在 docker-compose.prod.yml 中移除 ollama 服务，并将 `EMBEDDING_PROVIDER` 设为 `ollama` 以外的不匹配值（当前仅支持 ollama 和 openai）。

## 方式一：Docker 一键部署（推荐）

```bash
# 1. 下载项目
git clone <repo-url> && cd enterprise-insight-agent-v4

# 2. 下载预打包的 BGE-M3 模型包
#    从 Release 页面下载 bge-m3.tar.gz，放到 ollama-models/ 目录
#    或者跳过此步，让 Ollama 在首次启动时自动下载（较慢）

# 3. 一键部署
chmod +x deploy.sh
./deploy.sh

# deploy.sh 会自动：
#   - 检查 Docker 环境
#   - 创建 .env 生产配置（如不存在）
#   - 验证必填配置项
#   - 检查端口可用性
#   - 启动所有服务
#   - 等待健康检查通过
```

部署成功后访问 `http://localhost:8002`，使用默认账号登录：
- **用户名**：`admin`
- **密码**：`admin123`

## 方式二：手动部署

```bash
# 1. 配置环境
cp .env.production.example .env
# 编辑 .env，至少填写 DEEPSEEK_API_KEY、JWT_SECRET_KEY、POSTGRES_PASSWORD

# 2. 安装依赖
pip install -e ".[dev]"

# 3. 运行数据库迁移
alembic upgrade head

# 4. 种子数据（首次）
python scripts/seed_data.py

# 5. 确保 PostgreSQL、Redis、Ollama 服务已运行

# 6. 启动应用
uvicorn app.api.main:app --host 0.0.0.0 --port 8002
```

## 首次使用 5 分钟引导

### 1. 登录系统
浏览器打开 `http://localhost:8002`，使用 `admin / admin123` 登录。

### 2. 连接你的业务数据库
编辑项目根目录的 `customer_schema.yaml`：
```yaml
customer:
  name: "你的公司名称"
  database_type: postgresql
  database_url: "postgresql+asyncpg://用户名:密码@主机:端口/数据库名"
```

### 3. 自动发现数据库结构
```bash
# 获取 token
TOKEN=$(curl -s -X POST http://localhost:8002/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | python -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

# 发现 Schema
curl -H "Authorization: Bearer $TOKEN" http://localhost:8002/api/v1/admin/schema/discover
```

### 4. 配置字段映射
根据上一步返回的表和列，在 `customer_schema.yaml` 中填写物理表名和列名的对应关系。详细说明见 `customer_schema.yaml` 文件内注释。

### 5. 提第一个问题
在浏览器输入框中尝试：
- "本周华东区域销售概况"
- "退款率最高的 5 家门店是哪些"
- "会员等级分布情况"

## 常见问题

### Q: Ollama 启动很慢，一直在下载模型？
A: 下载 `bge-m3.tar.gz` 放到 `ollama-models/` 目录可以跳过在线下载。见 [方式一](#方式一docker-一键部署推荐)。

### Q: 端口冲突怎么办？
A: 编辑 `.env` 修改 `SERVER_PORT`、`POSTGRES_PORT`、`REDIS_PORT`、`OLLAMA_PORT` 等端口号，然后重启。

### Q: 企业内部服务器无外网怎么部署？
A: 1) 在有网络的机器上运行 `scripts/export-images.sh` 导出 Docker 镜像；2) 同时准备 `bge-m3.tar.gz` 模型包；3) 将所有文件拷贝到服务器，运行 `scripts/import-images.sh` 导入镜像，然后 `./deploy.sh`。

### Q: 默认管理员密码是什么？怎么修改？
A: 默认 `admin / admin123`。登录后通过系统界面修改，或通过 API 重置。

### Q: Docker Compose V1 vs V2？
A: `deploy.sh` 自动检测。优先使用 `docker compose`（V2 插件），如果不存在则降级到 `docker-compose`（V1）。

### Q: 数据库怎么备份？
A: 运行 `bash scripts/backup.sh`，备份文件保存在 `backups/` 目录。建议配置 cron 每日自动备份：
```
0 2 * * * /opt/eia/scripts/backup.sh >> /opt/eia/backups/backup.log 2>&1
```

### Q: 如何设置 HTTPS？
A: 推荐在服务器前面加一层 nginx 反向代理。参考 [Nginx HTTPS 配置模板](docs/nginx-https.md)。

## 通知接入：飞书 / 钉钉 / 企业微信（可选）

V4 检测到经营指标异常后，可自动推送消息到群聊。以飞书为例：

### 第一步：创建群机器人获取 Webhook URL

**飞书**：
1. 打开飞书 → 目标群聊 → 设置 → 群机器人 → 添加自定义机器人
2. 安全设置选"自定义关键词"，填 `经营`
3. 复制 webhook 地址：`https://open.feishu.cn/open-apis/bot/v2/hook/xxxxx`

**钉钉**：
1. 群设置 → 智能群助手 → 添加机器人 → 自定义（Webhook 接入）
2. 安全设置"自定义关键词"，填 `经营`
3. 复制：`https://oapi.dingtalk.com/robot/send?access_token=xxxxx`

**企业微信**：
1. 群聊 → 群机器人 → 添加
2. 复制：`https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxx`

> ⚠️ 飞书实测经验：安全设置选"签名校验"而非"自定义关键词"时，消息会被静默丢弃（返回 `Key Words Not Found` 错误码 19024）。建议先选"自定义关键词"或"无需安全校验"跑通测试，再加固安全策略。

### 第二步：配置 `.env`

```bash
# 通知 Webhook（可选，留空则不发送）
FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxxxx
DINGTALK_WEBHOOK_URL=
WECOM_WEBHOOK_URL=
```

只配一个平台即可，支持同时配多个。

### 第三步：验证

```bash
# 手动触发一次告警检查——如果群里收到消息，说明链路通了
curl -X POST http://localhost:8002/api/v1/alerts/check \
  -H "Authorization: Bearer whsec-你的N8N_WEBHOOK_SECRET"
```

### 定时推送（n8n）

n8n 已内置于 Docker Compose 中（端口 5680），**无需单独注册账号**。首次打开时按提示创建本地账号即可，数据存储在本地 Docker volume 中。

V4 已内置 2 个 n8n 工作流模板（`workflows/n8n-templates/`）：

| 工作流 | 功能 | 触发频率 |
|--------|------|---------|
| `alert-check.json` | 异常检测 + 推送 | 每 8 小时 |
| `weekly-report.json` | 周报生成 + 推送 | 每周一早 9:00 |

**导入步骤**：

1. 浏览器打开 `http://localhost:5680` → 首次访问按提示创建本地账号（邮箱+密码）
2. 点击右上角 **Import** → 选择 `workflows/n8n-templates/alert-check.json`
3. 同样导入 `weekly-report.json`

**替换密钥**（重要）：

导入后打开每个工作流，双击 HTTP Request 节点 → Headers → 将 `Authorization` 的值从占位符 `Bearer your-webhook-secret-here` 改成你的真实密钥：

```
Bearer whsec-你的N8N_WEBHOOK_SECRET
```

（`N8N_WEBHOOK_SECRET` 的值在 `.env` 中配置）

4. 点击右上角 **Publish**（发布）→ 左上角开关拨到 ON（激活）

> ⚠️ n8n 免费版不支持 Environment Variables，因此密钥需在工作流中手动替换。生产环境建议使用 n8n Credential Manager 或切回 APScheduler。
