## 四、验收中确认的三个真实发现

### 4.1 🐛 嵌入语义缺陷（修复，效果显著）
- **根因**：`save_analysis_history` 把「报告全文」做向量存库，而检索侧用「问题」做向量——短查询对长文做余弦检索，语义错位
- **附带**：391/778 条历史记录完全没有向量（保存时 Ollama 不可用）
- **修复**：存问题向量 + 全量回填 778 条
- **效果**：改写句召回率 **25% → 75%**，top-1 相似度 0.669 → 0.847

### 4.2 🔴 体系自检：Reflection 质检与用户满意度几乎零相关
- 质检通过的报告：不准确率 **28%**（27/97）
- 质检未过的报告：不准确率 **25%**（4/16）
- **结论**：Reflection 是否通过几乎不预测用户是否满意 → 质检的 4 个维度或判定阈值需重新审视（待下轮重构）
- **价值**：这是评估体系自检能力的直接产出——没有反馈闭环，这个产品级问题永远不会浮出水面

### 4.3 🟡 RAG SQL 命中 0% 的归因查明
- `analysis_history` 只存 Agent 最终回答（表格），**不存工具调用的 SQL** → `search_similar_sql` 正则提取拿不到内容
- 属存储设计缺口，修复路径已明确（data_sources 落库 + 迁移），待下轮实施

## 五、Reflection 对照实验（无质检 vs 有质检）

同批 12 条问题（Q01-Q04/Q51-Q54/Q89-Q92），实验组 `--skip-reflection` 绕过缓存真实执行：

| 指标 | 无 Reflection（skip） | 有 Reflection（正常） | 差值 |
|------|----------------------|----------------------|------|
| 通过率 | 83.3%（10/12，2 失败） | 100%（12/12） | -16.7% |
| 维度覆盖率 | 0.808 | 0.914 | -0.11 |
| 数值交叉校验 | 0.987 | 0.991 | -0.004 |
| SQL 执行成功率 | 93.5%（4/28 失败尝试） | 87.4%（11/91） | +6.1% |
| 平均延迟 | 49.7s | ——（缓存命中） | 不可比 |
| 实验状态标记 | 10 条消融 | 2 过 / 1 未过 / 9 跳过 | ✓ 三态生效 |

> **口径说明（诚实标注）**：实验组为绕过缓存的真实执行；对照组含缓存命中（内容为早前真实生成）。
> 方向性结论：**无质检时通过率与覆盖率下降，但交叉校验几乎不变**——与 §4.2「质检与用户满意度零相关」相互印证：
> Reflection 拦截能力有限，但去重它后报告质量确有可见回落，其价值在「兜底重写」而非「精准拦错」。
> 干净 A/B（双组同口径各 16 分钟）排期复跑：`eval_subset.py 8002 normal.json` vs `... noreflect.json --skip-reflection`。
> 实验基础设施验收通过：消融状态正确记录、绕过缓存、不污染生产缓存（§3 之 5 已证）。

## 七、结论与遗留

**结论**：V4.6.3 评估体系升级全部验收通过。评估体系从「规则代理指标」升级为「事实级校验 + 语义检索实测 + 用户反馈闭环」三层结构，并已产出 2 个真实系统缺陷（嵌入语义、质检零相关）和 1 个存储缺口（RAG SQL）。

**遗留（下轮）**：
1. `data_sources` 落库 + 迁移 → 解锁 RAG SQL 命中率
2. Reflection 质检维度/阈值重构（基于 4.2 的零相关发现）
3. 检索召回剩余 3 条边界用例的改写句优化
4. 对照实验干净复跑（双组同口径 16 分钟）
5. 评估集按 BadCase 扩充（Q01/Q13/Q21 高频不准确问题优先人工抽检）
